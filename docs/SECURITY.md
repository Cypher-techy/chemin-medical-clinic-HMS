# Security
bcrypt(12) password hashing, JWT (HS256, 8h, httpOnly, SameSite=Lax, Secure in prod) sessions, login-failure auditing, account suspension, server-side RBAC on every route, Zod validation on registration, Prisma parameterised queries, audit log append-only via API (protect with DB-level revoke in prod), break-glass requires justification + audit + governance review, M-Pesa callback secret + amount match + idempotency, secrets only in env (see .env.example), login rate limiting in-app (8 failures/15 min per account → 429, successful login resets) plus reverse-proxy rate limiting before go-live. Passwords: self-service change + audited admin reset (min 10 chars). Patient portal accounts are created by admin, linked to exactly one patient record; server returns 403 for any other record/list. MFA: TOTP (RFC 6238, `src/lib/totp.ts`) implemented — enrol in Admin → My MFA; login then requires a 6-digit code (verified live). Privileged accounts should be required by policy to enrol. Headers/CSP: configure in production proxy. Never expose clinical data via public website; intake endpoint is API-key + request-only.
