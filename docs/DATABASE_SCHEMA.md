# Database schema
See `prisma/schema.prisma` (source of truth, FKs, unique constraints: Patient.patientNo, User.email, Batch via medicine, MpesaTransaction.checkoutRequestId/receiptNo & Payment.reference for idempotency, SyncEvent.clientEventId). Key flows: Patient→Visit→Encounter→Prescription→Dispense→Batch (FEFO); Patient→LabOrder→LabTest (verify gate); Patient→Invoice→InvoiceItem/Payment. Signed Encounter rows are never updated except via Amendment rows (version++). Soft status fields instead of deletes for clinical/financial records. Runtime in this repo: dependency-free data layer (`src/lib/db.ts`, Node built-in SQLite, Prisma-shaped API, unique constraints in DDL) so the clinic node runs fully offline with zero native binaries. Production scale-out: use this schema.prisma with Prisma/PostgreSQL (`prisma migrate deploy`) — model/field parity is maintained in both files.
