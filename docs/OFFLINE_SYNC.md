# Offline & sync protocol
Local node runs the same app+DB (SQLite file or local Postgres) so registration, queue, triage, EMR, dispensing records and billing work without internet; emergency care never depends on connectivity/payment. Sync = explicit protocol (`POST /api/sync`), NOT bidirectional DB replication: globally unique IDs (cuid), `clientEventId` idempotency (replays return original event), timestamps+authorship in audit, conflict detection (`detectConflict`): signed encounters & verified payments are never overwritten — sync returns 409 CONFLICT for manual clinical/financial resolution, failed events remain visible on /sync dashboard. External notifications queue (QUEUED_NO_PROVIDER/QUEUED) and flush when providers/connectivity return. Outage tests: disconnect, restart, duplicate push, conflicting signed update — covered in TESTING.md.
